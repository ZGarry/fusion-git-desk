# Fusion Git Desk 性能审计与优化记录

状态日期：2026-06-05

## 结论

当前架构对几十个普通 Git 仓库已经够用，但在以下场景中仍需要主动限流：

- 工作区包含大量仓库，且每个仓库都要执行多条 Git 命令。
- 仓库里存在很大的未跟踪目录，例如未忽略的构建产物或依赖目录。
- 单个仓库有大 diff，前端一次性渲染过多文件和行。
- 自动刷新、自动 fetch、自动 pull 与手动操作同时发生。

本轮优化优先处理最容易造成卡顿的路径：状态扫描、未跟踪文件预览、diff 渲染和前端派生计算。

## 本轮已完成优化

### Git 状态扫描

- 将常规 `git status` 的未跟踪模式从 `-uall` 调整为 `-unormal`。
- 目的：避免未跟踪目录被递归展开成海量文件行。
- 影响：已存在目录中的新文件仍会显示；完全未跟踪目录会以目录项显示。

### 只读 Git 命令

- 所有 Git 子命令增加 `--no-optional-locks`。
- 目的：减少后台扫描和刷新时对 Git index 可选锁的干扰，降低与用户手动 Git 操作互相影响的概率。

### 未跟踪文件 diff

- 全量 working diff 不再读取前 30 个未跟踪文件内容。
- 全量视图只生成 metadata 摘要。
- 文件内容预览保留在文件级 diff 中，用户选中具体未跟踪文件后再读取。
- 目的：避免一次打开 diff 就读取大量磁盘内容、分配大量 diff 行对象。

### 前端渲染

- 仓库统计从多次 `filter` 改为一次遍历。
- 当前仓库查找从线性 `find` 改为 `Map` 派生索引。
- 变更文件列表限制为前 600 项渲染。
- diff 渲染限制为前 80 个文件、前 4000 行。
- 目的：防止 WebView 因超大 diff 或超多变更文件产生过多 DOM 节点。

## 性能取舍

- `-unormal` 比 `-uall` 更适合常规多仓库巡检，因为它避免了未跟踪目录递归爆炸。
- 全量 diff 牺牲了“未跟踪文件内容立即展开”，换来更稳定的首次加载性能。
- 文件级 diff 仍保持完整预览能力，因此深查某个文件的能力没有移除。
- 前端渲染上限不是最终虚拟滚动方案，但能先阻断最坏情况下的 UI 卡死。

## 后续建议

- 给 diff 面板接入真正的虚拟滚动，替代固定渲染上限。
- 给变更文件列表增加文件名过滤和虚拟列表。
- 扫描阶段加入耗时指标，记录每个仓库的 `status`、`log`、`remote` 花费。
- 评估把 `Inspect` 中的 `remote get-url` 和 `lastCommit` 做成延迟加载，首屏先返回状态。
- 给自动刷新增加“上一次扫描未完成则跳过”的运行日志，便于定位后台任务拥堵。
