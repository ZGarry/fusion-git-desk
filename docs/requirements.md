# Fusion Git Desk 需求规划

## 产品定位

面向同时维护多个代码仓库的开发者、集成负责人和交付人员，提供一个桌面端多仓库 Git 工作台。它不替代专业 IDE，也不追求覆盖所有 Git 命令，而是聚焦跨仓库状态聚合、风险识别、安全同步、分支查看与切换，并把代码审查、冲突处理和提交交还给 VS Code/IDEA。

一句话定位：让用户在一个窗口里看清很多仓库的状态，安全地检查远端、拉取代码、切换分支，并一键打开编辑器继续处理代码。

## 核心作用

- 降低多仓库巡检成本：不用在多个终端里反复进入目录执行 `status`。
- 降低批量同步风险：默认把“检查远端”和会改工作区的“拉取代码”分开，拉取只对无本地改动仓库执行安全快进。
- 降低分支处理成本：在同一个窗口里查看本地分支和远端分支，并切换当前仓库分支。
- 降低工具切换摩擦：从仓库状态直接打开 VS Code 或 IDEA，由专业编辑器负责提交、解决冲突和代码审查。
- 提升问题可解释性：把冲突、未关联远端分支、本地改动、远端落后、命令失败等状态暴露给用户。

## 核心能力

- 自动发现工作区下多个 Git 仓库
- 展示仓库状态、分支、远端、ahead/behind、最后提交
- 支持批量检查远端和仅无本地改动仓库拉取代码
- 支持查看本地分支、远端分支和切换当前仓库分支
- 支持用 VS Code 或 IDEA 打开当前仓库
- 用中文说明冲突、未关联远端分支、本地改动和拉取保护原因

## 基础闭环优先级

当前阶段优先完善基础能力，不优先展开深度功能。每轮需求选择前先检查这些问题：

1. 扫描是否可靠：能否发现工作区内仓库，并在失败时说明原因。
2. 状态是否可信：分支、远端、ahead/behind、本地改动、冲突和远端关联状态是否清楚。
3. 分支是否可用：本地分支、远端分支和切换分支操作是否清楚、稳定、可恢复。
4. 同步是否安全：检查远端、拉取代码、自动拉取的边界是否显式，并保护有本地改动的工作区。
5. 打开编辑器是否可靠：VS Code/IDEA 打开失败时是否有明确原因。
6. 验证是否成立：改动是否有自动测试、构建或可重复手动验收方式。

只要这些基础闭环里存在 P0/P1 问题，就不应优先做后台托盘、复杂分组、深层缓存、复杂发布体验等深入事项。

## 值得优化的问题

- P0：会破坏用户工作区、导致数据丢失、构建测试发布失败、核心流程无法使用的问题。
- P1：用户在日常多仓库巡检中反复遇到的卡顿、误解、错误不可见、安全边界不清或操作闭环断裂。
- P2：明确提升效率但不影响基础闭环的体验改进，例如过滤、排序、轻量提示和文档补强。

暂不值得优化的问题：

- 没有用户场景或测量依据的深度性能重构。
- 为未来大功能提前铺设的大抽象。
- 会扩大 Git 写操作范围但没有足够保护和验收的功能。
- 只让内部结构更漂亮、但不改善用户基础流程的改动。

## 后续路线

- 仓库收藏、分组、标签
- 明确保护后的单仓库或批量推送
- 系统托盘和后台计划任务
- manifest 导入导出
